# Анализатор прохождения КТК

Ядро анализа перенесено с Python на C#. Для работы программы Python и `main.py` больше не требуются. При обычном запуске ядро выполняется внутри приложения; при отладке Visual Studio автоматически используется изолированный процесс того же `Analizator.exe`, чтобы отладчик не прерывал обработку Excel.

## Состав решения

- `Analizator` — WPF-интерфейс и встроенное ядро анализа Excel-книг.
- `Analizator.Cli` — консольный запуск того же ядра для автоматизации.
- `Analizator.Core.Tests` — автономные характеризационные и сквозные тесты.

Обработка Excel реализована на .NET 8 и ClosedXML 0.105.1. Ядро сохраняет существующий формат книги: месячные блоки, лучшие результаты по сценариям, признак прохождения, условное форматирование, сводный лист, график посещаемости и служебные отчёты.

На странице «Обработка» источник результатов выбирается отдельно: можно использовать обычную Excel-выгрузку или локальную базу данных. Для базы программа показывает только доступные календарные месяцы и формирует один месяц за запуск. Перед запуском выводятся количество учитываемых записей, исключённых точных повторов, возможных повторов и записей без режима. Таблица анализа Excel остаётся шаблоном результата в обоих режимах.

В разделе «База данных» доступно локальное хранилище SQLite. Можно выбрать несколько выгрузок за разные месяцы одним действием; старый и текущий форматы определяются автоматически. База хранит каждую попытку с датой, ФИО, установкой, сценарием, процентом, режимом и ссылкой на исходную строку. Повторная загрузка того же файла блокируется по его содержимому. История источников позволяет удалить данные отдельного файла; перед удалением автоматически создаётся резервная копия базы.

Перечень установок в `config/installations.json` применяется ко всем выборкам базы. Названия листов Excel и `PlantName` из JSON сопоставляются с каноническими названиями и синонимами; распознанные синонимы сохраняются под названием из настроек. Несопоставленные записи не участвуют в поиске, статистике и выгрузках, а программа показывает предупреждение с названиями, которые нужно добавить в настройки. При изменении списка уже сохранённые распознанные синонимы автоматически объединяются с канонической установкой.

Кнопка «Редактировать записи» открывает встроенный редактор с поиском по ФИО, установке, сценарию и источнику, отдельными фильтрами по дате и времени, добавлением, изменением и удалением отдельных попыток. Дата и время хранятся в SQLite в отдельных индексированных полях `attempt_date` и `attempt_time`; исходное полное значение также сохраняется для совместимости. Все найденные записи показываются единым виртуализированным списком без переходов между страницами. Кнопка «Столбцы…» позволяет скрывать ненужные поля; выбор сохраняется между запусками.

Кнопка «Сформировать выгрузку…» создаёт из базы книгу Excel за отдельный месяц или произвольный диапазон дат. В окне можно отметить нужные листы-установки и столбцы. Фильтр по ФИО необязателен: если никого не отмечать, в файл попадут все сотрудники выбранных установок. Итог повторяет структуру обычной выгрузки КТК: для каждой установки создаётся свой лист с параметрами и таблицей отчётов. Точные повторы исключаются автоматически, возможные сохраняются для проверки. Даты и продолжительность сохраняются как типизированные значения Excel.

Кнопка «Статистика» открывает отдельное окно формирования подробного фактического отчёта из локальной базы. В нём выбираются произвольный период, одна или несколько установок и правило учёта возможных повторов. Действующий общий или индивидуальный порог прохождения применяется автоматически. Итоговая книга содержит сводные показатели и редактируемые диаграммы, статистику по каждому сотруднику, установке и сценарию, помесячную динамику, распределение по режимам, контроль качества данных, исходные записи и описание методики. В расчёты входят успешность, средний, медианный, лучший и худший результаты, активность, интервалы между попытками, динамика результата, стабильность, серии успешных попыток, длительность и количество действий. Точные повторы всегда исключаются, а дата и время на листе исходных записей сохраняются в отдельных типизированных столбцах Excel.

Кнопка «Мониторинг» формирует сразу две книги: подробный расчёт в структуре Python-модуля (`Статистика`, `Сотрудники`, `Детализация`, `Диагностика`) и заполненную копию годовой формы сбора. В строку «Кол-во прохождения сценариев» записывается квартальное число уникальных сочетаний «технический объект + сотрудник + сценарий»; одинаковый сценарий на разных объектах считается разным. В форму попадают только кварталы, полностью покрытые выбранным календарным периодом.

Кнопка «Фото в PDF» рекурсивно проверяет выбранную папку отчётов, поэтому поддерживает структуру `папка отчётов / установка / папка запуска / PDF` и более глубокую вложенность. Итоговая книга содержит сводку по установкам и фильтруемую таблицу с ФИО, датой, сценарием, режимом, наличием фотографии, числом найденных изображений и ссылкой на исходный PDF. Фотографией считается встроенное растровое изображение размером не менее 100 × 100 пикселей; повреждённые и нераспознанные отчёты не теряются, а помечаются в столбце «Примечание».

В разделе «Настройки» доступно отдельное окно резервных копий базы. Можно включить автоматическое копирование и задать интервал в днях, количество сохраняемых копий, создание копии перед изменением или удалением, а также подтверждение удаления отдельной строки и целого загруженного файла. По умолчанию автоматическая копия создаётся раз в 15 дней, перед изменениями база страхуется, а в `data/backups` остаются две последние копии.

Повторы определяются по составному ключу: установка, нормализованные ФИО и сценарий, дата, время до секунды и процент. Полное совпадение получает статус «Точный», связывается с основной записью и не учитывается повторно при анализе, но физически остаётся в базе. Если те же поля совпадают, а время отличается не более чем на 60 секунд, запись получает статус «Возможный» и остаётся в анализе до ручной проверки. При совпадении JSON и Excel основной считается JSON-запись: режим прохождения читается из `TrainingTimes.Mode`. Редактор позволяет показать только повторы и выводит основание присвоенного статуса.

В базу можно одновременно загружать книги Excel `.xlsx`/`.xlsm` и выгрузки КТК Лаунчера `.json`. Для JSON каждая запись `ExerciseReports` сохраняется как отдельная попытка; установка берётся из `PlantName`, поэтому один файл может содержать несколько установок. Вместе с результатом сохраняются поля сеанса и отчёта: `Guid`, `MachineName`, `StudentSerial`, даты сеанса, `Role`, `Resume`, `Result`, `Steps`, `TimeSpent`, признаки валидности и наличия отчёта, пути к отчёту, а также исходные `TrainingTimes` и `ExerciseLogs`.

Если выгрузка содержит повреждённый кэш сводной таблицы, импорт удаляет только эти служебные объекты из временной копии в памяти и продолжает чтение исходных строк. Оригинальный файл не изменяется. После обновления правил импорта уже загруженный файл можно выбрать снова: база автоматически пересоберёт его записи новой версией парсера без ручного удаления источника.

## Сборка и проверка

Требуется .NET 8 SDK под Windows.

```powershell
dotnet restore .\Analizator.slnx
dotnet build .\Analizator.slnx --configuration Release --no-restore
dotnet run --project .\Analizator.Core.Tests\Analizator.Core.Tests.csproj --configuration Release --no-build
```

Запуск интерфейса:

```powershell
dotnet run --project .\Analizator\Analizator.csproj --configuration Release
```

Для профиля Visual Studio отключён Hot Reload. Кроме того, тяжёлая обработка ClosedXML под F5 вынесена в дочерний C#-процесс без подключения отладчика. Интерфейс остаётся доступен для отладки, а `CORDBG_E_TIMEOUT` во время перестроения Excel-книги не завершает программу.

Порог прохождения настраивается в разделе «Настройки» → «Настроить пороги…». Флаг включает индивидуальный режим по установкам; при выключенном флаге ко всем установкам применяется единый порог. Допустимы значения от 0 до 100%, значение ровно на пороге считается проходным. Если блока `passing_threshold` нет в старом `settings.json`, используется прежнее значение 10%.

При первом запуске интерфейс использует прежнюю рабочую папку `C:\Users\MSI\Desktop\АП`, если в ней существует каталог `input`. Путь можно изменить на экране «Настройки». Рабочая папка имеет структуру:

```text
input/    исходные книги Excel и выгрузки JSON
config/   рабочая JSON-конфигурация
output/   результаты и резервные копии
logs/     журналы обработки
data/     локальная база SQLite и её резервные копии
```

Файлы JSON-конфигурации интерфейса находятся в каталоге `config` выбранной рабочей папки. Интерфейс читает и сохраняет именно эти файлы; скрытых рабочих копий рядом с исполняемым файлом нет.

Основной файл базы: `data/analizator.db`. Сетевой сервер и отдельная установка SQLite не нужны: необходимая библиотека поставляется вместе с программой.

## Консольный запуск

```powershell
dotnet run --project .\Analizator.Cli\Analizator.Cli.csproj --configuration Release -- --analysis "C:\data\input\Анализ_прохождения 2026_08.xlsx" --export "C:\data\input\Выгрузка_КТК_МНПЗ_август_2026.xlsx" --output-dir "C:\data\output" --config-dir "C:\data\config" --create-backup --auto-add-new-people
```

Обязательны `--analysis` и `--export`. Автодобавление можно отключить параметром `--do-not-auto-add-new-people`.

## Совместимость

Миграция сохраняет наблюдаемое поведение прежнего ядра, включая пороги нечёткого сопоставления, правила автодобавления и формирование листов. Поле `mode_filter` в `settings.json` оставлено выключенным на уровне конвейера: прежний загрузчик также не передавал его в обработку, несмотря на значение `enabled` в JSON. Это сделано намеренно для совпадения рабочих результатов; включение фильтра следует оформлять отдельным изменением бизнес-логики.

Контрольный прогон на августовских рабочих файлах дал 8 445 отчётов, 834 сопоставленных сотрудника и 95 отсутствовавших в выгрузке — те же итоговые показатели, что и прежнее ядро.
