# Анализатор прохождения КТК

Ядро анализа перенесено с Python на C#. Для работы программы Python и `main.py` больше не требуются. При обычном запуске ядро выполняется внутри приложения; при отладке Visual Studio автоматически используется изолированный процесс того же `Analizator.exe`, чтобы отладчик не прерывал обработку Excel.

## Состав решения

- `Analizator` — WPF-интерфейс и встроенное ядро анализа Excel-книг.
- `Analizator.Cli` — консольный запуск того же ядра для автоматизации.
- `Analizator.Core.Tests` — автономные характеризационные и сквозные тесты.

Обработка Excel реализована на .NET 8 и ClosedXML 0.105.1. Ядро сохраняет существующий формат книги: месячные блоки, лучшие результаты по сценариям, признак прохождения, условное форматирование, сводный лист, график посещаемости и служебные отчёты.

## Сборка и проверка

Требуется .NET 8 SDK под Windows.

```powershell
dotnet restore .\Analizator.slnx
dotnet build .\Analizator.slnx --configuration Release --no-restore
dotnet run --project .\Analizator.Core.Tests\Analizator.Core.Tests.csproj --configuration Release --no-build
```

Запуск интерфейса:

```powershell
dotnet run --project .\Analizator\Analizator.csproj --configuration Release
```

Для профиля Visual Studio отключён Hot Reload. Кроме того, тяжёлая обработка ClosedXML под F5 вынесена в дочерний C#-процесс без подключения отладчика. Интерфейс остаётся доступен для отладки, а `CORDBG_E_TIMEOUT` во время перестроения Excel-книги не завершает программу.

Порог прохождения настраивается в разделе «Настройки» → «Настроить пороги…». Флаг включает индивидуальный режим по установкам; при выключенном флаге ко всем установкам применяется единый порог. Допустимы значения от 0 до 100%, значение ровно на пороге считается проходным. Если блока `passing_threshold` нет в старом `settings.json`, используется прежнее значение 10%.

При первом запуске интерфейс использует прежнюю рабочую папку `C:\Users\MSI\Desktop\АП`, если в ней существуют каталоги `input` и `config`. Путь можно изменить на экране «Настройки». Рабочая папка имеет структуру:

```text
input/    исходные книги Excel
config/   JSON-конфигурация
output/   результаты и резервные копии
logs/     журналы обработки
```

## Консольный запуск

```powershell
dotnet run --project .\Analizator.Cli\Analizator.Cli.csproj --configuration Release -- --analysis "C:\data\input\Анализ_прохождения 2026_08.xlsx" --export "C:\data\input\Выгрузка_КТК_МНПЗ_август_2026.xlsx" --output-dir "C:\data\output" --config-dir "C:\data\config" --create-backup --auto-add-new-people
```

Обязательны `--analysis` и `--export`. Автодобавление можно отключить параметром `--do-not-auto-add-new-people`.

## Совместимость

Миграция сохраняет наблюдаемое поведение прежнего ядра, включая пороги нечёткого сопоставления, правила автодобавления и формирование листов. Поле `mode_filter` в `settings.json` оставлено выключенным на уровне конвейера: прежний загрузчик также не передавал его в обработку, несмотря на значение `enabled` в JSON. Это сделано намеренно для совпадения рабочих результатов; включение фильтра следует оформлять отдельным изменением бизнес-логики.

Контрольный прогон на августовских рабочих файлах дал 8 445 отчётов, 834 сопоставленных сотрудника и 95 отсутствовавших в выгрузке — те же итоговые показатели, что и прежнее ядро.
